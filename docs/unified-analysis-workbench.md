# 统一分析工作台

平台的发展方向是轨道车辆智能故障分析与三维可视化。本阶段验收范围是运行数据异常分析、证据回查与故障相关结构示意。

本阶段以 `codex/product-workbench-20261113` 的 `ef887f2` 为基础。该版本已经包含 `main` 的提交，以及离线 GLB、转向架动画、历史回放、剖切和零件检查。开始重构前，把工作区中已验证的 AI 输出校验修复单独提交到新分支；重构改动在其上开发。

| 原有页面或入口 | 分类 | 现在的用法 |
| --- | --- | --- |
| 首页最近批次趋势、统计与异常演示、运行分析 | 核心与辅助原先并列 | 默认打开分析工作台，在同一处选择历史批次或内置虚构数据。运行分析承载正式曲线和异常回查。原首页保留为高级工具中的「数据总览」，用于浏览数据就绪情况及最近导入。 |
| 车辆档案、CSV 导入、批次回执 | 核心数据准备 | 「车辆与数据」只保留建档与导入。回执继续带车辆和批次返回分析工作台。 |
| 三维转向架、运行回放、剖切、量测、零件选择与检查 | 核心观察及辅助工具 | 曲线页的入口打开整批回放，异常事件入口定位到相应样本。返回恢复原分析条件。现有三维教学、模型、渲染和工具保留。 |
| AI 证据核查、主动解读、解读历史 | 核心证据与辅助历史 | 从当前分析进入证据视图。虚构演示只显示当前范围的离线证据；本机 AI 历史也可由高级工具打开。 |
| 单批次 PDF、采样质量 | 核心交付与辅助质量检查 | PDF 和采样质量各有一个标签。更改批次、筛选或报告来源后，失效的 PDF 不再提供下载。 |
| 同车多批次、驾驶舱、振动与平稳性、多车对比、机器学习、演示中心 | 高级或实验 | 从「高级工具」按需打开，保留原有算法、数据来源、可用的报告与解读流程。同车多批次使用运行分析原有实现，没有新增独立页面。 |

旧 `rail_page` 链接仍能进入原有视图。公开演示版以虚构分析为默认视图，不开放历史批次、导入、本机 AI 历史或在线解读。

工作台的统计与报告以所选批次、时间范围和阈值为准。整批回放带入该批次和阈值，时间轴仍覆盖整批；异常入口定位当前筛选内的特定观测。虚构证据与 PDF 使用同一筛选范围，数据不会写入数据库。规则超阈值、测得的加速度、示意模型动作和 AI 提出的待核实原因是不同信息；本项目不提供真实故障确诊。

从工作台进入当前批次的证据核查，再从所选异常进入三维后，可返回同一条证据，或直接回到原分析范围。返回记录仅保存在当前会话；从侧栏进入其他工具会结束这条路径。历史归档、旧链接及独立教学模式仍按各自的入口使用。

长批次的工作台曲线和异常标记每条序列最多画 4,000 个原始点，保留首末点及分段极值。缩小时间范围可查看细节。规则统计、事件证据和 PDF 输入仍使用全部筛选样本，PDF 原有出图方式不变。仅在生成报告或已有报告可下载时校验报告指纹。用 50,000 条、每 10 毫秒一条的内存虚构样本运行 Streamlit AppTest，预热后各跑三次，中位耗时从约 0.96 秒降到 0.46 秒，图表 JSON 从 6.57 MB 降到 0.82 MB；这项测量不含 SQLite 读取或浏览器绘图。

浏览器验收使用独立的 `RAIL_PORTABLE_HOME` 和 `AI_ENABLED=false`。启动本机完整版，在测试库登记虚构车辆 `DEMO-001`，导入 `scripts/generate_demo_data.py` 生成的 `demo_run_2.csv`。在已安装 Playwright 的 Node 环境执行 `node scripts/check_analysis_workbench_browser.cjs http://127.0.0.1:8518 screenshots`，把端口换成测试实例的端口。脚本核查 54 部件 GLB、证据与三维往返、PDF 下载和两种窗口尺寸，并保存截图。
