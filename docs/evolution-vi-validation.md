# Evolution VI 实验验证与观测融合

## 基线及审计

从 Evolution V `58372b11` 出发。独立运行基线 pytest 得到 754 项测试及 324 个子测试。已正常推送该基线至远程 `codex/evolution-v-wheel-rail`，VI 使用独立的 `codex/evolution-vi-validation`。检查范围包括 31 自由度等效锥度与摩擦力、轨道截面零点、左右悬挂静载与坐标符号、GLB 机械层级、SQLite 和数字孪生历史版本。原整车计算的主要边界为刚性轨道、单侧法向点接触、等效锥度和固定工况速度。本轮将新型面和柔轨作为独立可验证模型接入，避免给历史结果替换模型定义。既有 54 部件几何继续支持原三维检查流程。本轮增加截面及单组件状态位置图。

## 工程验证中心

「工程验证中心 → 基准对照」运行 0.8 s 轮轨垂向试验。内置 Radau 结果用于对照 DOP853。授权参考 CSV 使用 `time_s,value`，并登记出处、版本、使用范围、时间起点和通道单位。时间必须递增，共同区间须覆盖计算时窗至少 80%，无外推、自动时移或大缺口跨越。输出 RMSE、MAE、峰值误差、相关系数及参考原文件 SHA-256。RMSE 门槛为本次试验的声明值。PDF 为结果摘要，JSON 保存每个公共样点、原始来源声明与计算配置。

验证等级分为解析、数值交叉、外部公开基准、独立台架、实车。上传台架或实车文件属于用户来源声明，现场条件与仪器仍需独立核对。合成参考与数值互验用于验证模型实现。

## 轨道柔度组件与不确定性

以两质量 `mw,mr` 表示半轮对与钢轨等效质量。轮侧悬挂及轨下垫层各有刚度和阻尼。使用向上为正的 `zw,zr`，在已声明的静载 `Q0` 附近有 `Q=KH·max(δ0+zr−zw,0)^(3⁄2)` 及 `δ0=(Q0/KH)^(2⁄3)`。轮侧响应为 `mw·zw''=Q−Q0−kw·zw−cw·zw'`。轨侧为 `mr·zr''=(α−1)Q0−αkr(zr−u)−cr(zr'−u')−(Q−Q0)`。平滑脉冲提供轨下不平顺 `u` 和局部支承比例 `α`。线性化版本使用 Hertz 在预压量处的切线。用矩阵指数验证线性自由响应，用静载零输入及独立 Radau 核验非线性。

默认 12 个配对扰动下，对轨下阻尼加 25% 的候选复算，轮重波动 RMS 改善的经验 5／50／95 分位为 10.503／17.031／34.042 N。以声明的最小轮重／静载 0.75 为门槛，候选为 0/12 超限，最不利样本的独立求解差约 0.0000112 N。该区间仅描述本次采样与模型。输入相关性及每组参数在 JSON 中保存。

另用 V 的 22 m/s、半径 450 m、右二系从 90% 恢复缺口的 75% 算例，将锥度和左二系阻尼共同乘以 0.9、1、1.1。三个配对的横向 RMS 收益分别为 0.000325、0.000332、0.000335 m/s²。在该窄范围内收益相近且大于该名义点的求解器复算差。名义基线 RMS 在三个工况间变化近 0.00145 m/s²，仍需采用更广泛独立扰动、模型参数误差和台架数据评估工程显著性。

## 状态观测与监测证据

「数字孪生 → 在线采集与状态估计」用模拟源检查增益、偏置、单位、正方向、共同触发、设备固定偏移、50 Hz 对齐、序号缺口和暂停恢复。同步接收容许偏离公共采样格 ±2.5 ms，超限记录保留在原始证据并拒绝融合。会话缓冲保存原始包和计数。JSONL 首行为声明，后续为 `device,seq,timestamp_us,value` 等价 JSON 对象；设备 CSV 可与同一 JSON 声明配对。上传导入后可重新回放原时间轴，导出原始记录与处理后的估计时程。设备登记示例由界面生成。原始状态和估计分别标记。

可选 WebSocket 采集桥使用本机端点和可恢复的全局序号。安装已有环境所需的 `stream` 可选依赖后运行 `python -m scripts.record_sensor_loopback ws://127.0.0.1:8765 demo.jsonl`。客户端申请 `{"resume":100}`，桥接端确认同一序号和 `declaration`，逐条发送 `{"index":100,"packet":{...}}`，完整结束用 `{"end":下一序号}`。更换声明、错误序号或超出缓存时拒绝拼接，输出路径用新建模式。该工具经本机断线续传测试，串口、MQTT、手机及实车接入需由已授权桥接设备提供。

状态估计用带已知输入力的二状态垂向分量 `[z,v]`。通过指数精确离散零阶保持输入，用 Van Loan 积分过程噪声，依位移、加速度分别更新，Joseph 形式保持协方差，拒绝超出五倍标准差的观测。短激励缺口沿用最近样本，超过 3 个采样间隔即清除状态。检查近时窗的观测秩和协方差后才展示估计和条件区间。实时三维表示有依据的单轴支座位置，状态曲线区分单位换算后的观测、预测、估计和虚构真值。

将当前记录交给 Copilot 并输入「检查当前数据流异常，核查时钟并比较悬挂退化假设」。本地工具核对采集摘要及时钟后，用固定激励复算名义、刚度变化、阻尼变化、传感器偏置和激励比例五种假设，在后半段留出窗口排名，并输出 Welch 主峰和独立核查建议。偏置和比例仅从前半段拟合。时间或激励缺失时不排序。教学示例的 953 个有效包和 7 个序号缺口均可回查，预置阻尼变化的留出加速度 RMSE 约 0.0844 m/s²。候选排名和滤波协方差仅对应声明模型及数据。

## 独立设备准备

1. 在未安装 Python 的 Windows x64 设备上解压完整目录，双击 EXE，检查普通用户目录与默认浏览器启动。核对构建清单 SHA-256，重复启动、退出和重启后检查隔离数据保留。
2. 在工程验证中心完成 Radau 复算和两个授权型面的上传，用报告记录时间基准、载荷状态、文件摘要及单位。对照加载与无载项。
3. 在数字孪生运行虚构记录、断线恢复、录制再导入及 Copilot，检查观测、估计、缺测和警报来源。外部设备须获取授权、登记共同触发及校准，并采集独立参考激励、位移和加速度。未知时基和标定须保留状态。
4. 使用便携目录内的「公测反馈模板」记录系统版本、分辨率、复现步骤、错误信息和构建编号。时间同步和载荷对照另行保存原始声明、参考设备不确定度和日志。不要在反馈中包含个人数据或凭据。
