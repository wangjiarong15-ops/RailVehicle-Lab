# Evolution IV 车辆数字孪生与工程优化

基线为 `5a1ac8ed`，来自 Evolution III。原 19 自由度 Newmark 求解器、54 部件 GLB、三维历史回放和 Copilot 通常分析流程继续使用。第四阶段使用独立分支 `codex/evolution-iv-twin`。

## 观测、模型和时间

- 在左侧打开「数字孪生」。虚构试验包含训练和验证各一份记录。它们使用 65 Hz 和 51 Hz、不同轨道输入、不同随机种子，以及已知的独立时钟偏移和时钟速率。
- 工程配对记录包含每份观测的长表 CSV、元数据 JSON、动力学工况 JSON。CSV 表头为 `time_s,channel,value,unit`。时钟定义为 `t_model = clock_scale · time_s + offset_s`。同一文件中各通道可异步采样，每通道须按时间严格递增。工作台可以根据上传的工况文件下载带对应激励摘要的元数据模板。
- 单位按元数据显式转换。速度支持 m/s 或 km/h，加速度支持 m/s² 或 g，侧滚角支持 rad、mrad 或 deg，二系相对位移支持 m 或 mm。CSV 中加速度的 SI 单位标记写作 `m/s^2`。加速度映射到模型质心或指定动态轴，二系位移为车体减构架的定义。在已有安装信息不足时，历史加速度通道保留原观测含义。
- 数字孪生对比使用已声明的车、激励及共同触发记录。时间同步系数须来自采集系统或标定记录。相对时钟偏移可登记，未知漂移不自动估计。速度须覆盖计算窗并与匀速模型相符。对比由模型插值到原观测时刻。回放界面附近读数使用最近合格样本，不跨空档补数。导出保留原 CSV 行号、文件和元数据 SHA-256、传感器配置版本、模型版本及计算证据。
- 普通历史批次提供观测时间轴、运行曲线、批次溯源、传感器版本和原三维回放入口。通用运行 CSV 需要额外的激励、时钟及测点说明才具备模型校准条件。当前工具使用用户声明的实测记录或标记清楚的合成记录，实车实时采集仍待接入。

## 参数辨识和独立验证

辨识使用 19 自由度模型的等价 9 自由度横向子系统。前后构架与车体的横移、侧滚和摇头通过悬挂耦合。纵向速度固定，轮对横向由轨面规定。拟合参数为二系横向刚度、二系横向阻尼和等效抗侧滚刚度。固定其他质量、几何及悬挂参数，保留输入数据和模型配置的追溯关系。

采用有界两起点非线性最小二乘，各通道误差按训练观测标准差及数值分辨率下限归一化。使用数值灵敏度矩阵的 SVD 检验秩和条件数。触及参数边界、起点分歧、响应不足或独立验证不理想时，不输出可用于优化的参数。验证记录须来自同车，训练和验证使用不同记录。训练使用 1 ms 步长，独立记录验证采用 0.5 ms。局部 95% 区间采用线性化和独立等方差残差假设，未纳入激励、几何与其他固定参数的不确定度。

虚构参考真值为 142 kN/m、21 kN·s/m、250 kN·m/rad。为训练和独立验证分别添加 2% 和 3% 的通道标准差等比例噪声。该基准检查已知时钟映射、恢复误差、基准与拟合残差和现有 19 自由度全模型的输出一致性。

## 多工况优化和响应观察

优化计划可设置设计变量上下限、目标和权重、速度与轨道激励组合、侧滚及行程上限与求解次数。支持规则网格、局部坐标搜索、确定性种子的空间填充全域探索、组合搜索。目标使用各工况中最不利的数值再归一化。每轮预留足够预算给基准及候选半步长复算。候选任一工况超约束、线性轮轨接触失效或复算偏差过大时排除。Pareto 集取自已复算候选，有限采样可能遗漏其他可行方案。垂向 RMS 可作为联合目标，当前三个设计变量只影响横向子系统。

工程优化中心可直接对工况做试算，也可使用同一配对记录刚复核的辨识参数。三维双窗同步显示基准和方案，支持透视、游标、峰值、倍速和逐帧。着色是绝对二系横向计算位移，蓝色 0 mm 至橙色 20 mm，范围外饱和显示。几何仍沿用通用示意和既有 Blender GLB。

残差复核按用户阈值和原始行号定位。四段 RMS 提供当前记录内的变化趋势。采样足够且均匀时可查看 Welch 残差谱。刚度和阻尼分别降低 20% 的选项用于对照教学假设。残差相关和最接近的假设需要额外证据才能支持机械原因。

## 审批、证据和复算

从当前观测跳到 Copilot，可以输入「校准当前车辆动力学模型，二系横向刚度 85–260 kN/m，侧滚不超过 4 mrad，完成参数优化、复算和报告」。系统识别后一项工程流程，并在「审批与任务」显示可编辑的范围和预算。常规多轮问答、已有资料检索和工具保留。工程任务走确定性本机执行路径，无需模型 API。任务可暂停、继续或取消，重试从未完成阶段开始。跨进程复算通过 SQLite 归档恢复请求，虚构记录可按版本重新生成，实测记录须重新绑定相符的原文件。

工程任务产生带 SHA-256 的 JSON 证据及 PDF 摘要。批准的本机任务通过新增的 `twin_research_history` 表归档，历史车辆数据库的既有表保持原结构。核心文件为 `twin_data.py`、`twin_identification.py`、`twin_optimization.py`、`twin_monitoring.py` 与 `twin_workflow.py`。

当前限制包括实时设备接入、独立实车精度验证、非对称悬挂、非线性轮轨和实车装配干涉校核。台架阶段需要同车、同一时基的轨面输入、车体横向加速度、侧滚角、二系相对位移和参考仪器不确定度，再以多个独立工况检验参数稳定性。

## 本机验收

- Evolution III 基线复核为 731 项 pytest、324 个子测试及双分辨率 Edge 专项。Evolution IV 完整 pytest 为 743 项、324 个子测试，失败 0。Python 编译、JavaScript 语法、GLB 校验和跨版本契约均通过。
- `python scripts/run_browser_checks.py --suite all` 最终在真实 Edge 中退出成功。新专项核对六文件导入、Copilot 审批中的明确参数范围、同步双视窗、PDF 下载和在全新会话复算归档。旧专项继续覆盖观测批次溯源、注册传感器、导航、三维回放及 Copilot 本机模拟接口。
- 已知噪声算例辨识出 141.901 kN/m、21.003 kN·s/m 和 253.639 kN·m/rad。独立验证归一化 RMSE 由 0.17884 降至 0.02902。模型通过训练与验证两工况的线性接触筛查。测试复核涉及尾轴输入不完整、重复时间、通道不足或接触载荷异常的拒绝路径。
- 示例批准范围为二系横向刚度 85–260 kN/m，侧滚上限 4 mrad，二系横向行程上限 20 mm。60 次辨识/接触筛查求解与 28 次优化/复算求解后，最不利横向 RMS 从 0.05898 降至 0.03232 m/s²，侧滚峰值从 0.5984 降至 0.4051 mrad。二系最大横向行程从 5.234 增至 6.401 mm。该次本机任务约 5.8 秒。结论只对应两种指定激励及当前教学参数。
- 对 100 Hz、4 Hz 正弦残差的 Welch 数值对照得到 3.90625 Hz 峰值，频率分辨率 0.390625 Hz。PDF 已渲染并检查单位及证据编号。
- 在本机 Windows 11 x64 对源码提交 `35e0eb33` 进行了 PyInstaller 目录式构建。EXE 使用临时 `LOCALAPPDATA` 及无 Python 入口的进程 PATH 启动，在真实 Edge 中通过双分辨率数字孪生专项，包括本地服务健康检查、六文件导入、辨识、双视窗、PDF 与 SQLite 归档复算。独立无 Python Windows 机器验收仍待进行。
