## 标题（建议）

RailVehicle-Lab：把转向架三维结构与运行数据证据放在同一块屏幕的可溯源工程教学演示

## 一、自我介绍

【姓名/昵称，可选】。【学校/单位，可选】。我的日常是把轨道车辆工程的计算规则做成可交互的教学工具：
此前已用 Python/Streamlit 完成本地完整版 RailVehicle-Lab（CSV 解析、异常判定、统计与回放、本地数据库）。
本次参赛提交的是它的**在线参赛版**：纯前端、打开链接即用、无需安装/账号/API 密钥。

## 二、作品是什么

一个面向车辆工程教学与评审演示的 Web 应用，五个入口：

1. **工作台**：定位、能力边界、三分钟导览入口；
2. **运行分析**：三通道共轴曲线、阈值与异常事件带、统计卡、统一时间轴、证据面板；
3. **三维转向架**：真实 GLB 装配的零件点选/高亮/隔离、传感器测点与方向标签；
4. **教学仿真**：预设工况包络的构架/轮对/悬挂联动示意动画（明确标注非诊断、非实车）；
5. **项目说明**：架构、双版本差异、工程局限。

核心差异点：**每个异常事件可溯源到原始 CSV 的物理行号**，曲线游标、时间轴读数、三维回放与证据面板
共用同一游标；判定口径与本地 Python 版逐字对齐（56 项浏览器单测以 Python 输出为基线）。
所有示例数据带琥珀色「虚构演示 · 非实测」徽标；导入自有 CSV 仅在浏览器本地解析，徽标「本地导入 · 未上传」。

公网地址（Qoder Sites 部署，无需任何准备）：<https://railvehicle-bogie-d1j7uxpvtu6.qoder.zone/>

## 三、为什么开发

- 教学痛点：转向架结构靠挂图、运行数据靠表格，两者分离，学生难以把「异常样本」对应到「结构位置」；
- 工程痛点：分析结论若不能回查原始行号与判定规则，就只是黑箱输出，无法用于教学讨论与复核；
- 评审痛点：完整工程工具依赖 Python 环境与数据准备，评委无法在三分钟内亲手走完闭环。
因此在线版的目标不是堆功能，而是**可溯源、可复现、口径诚实**：统计来自真实计算，动画明确是教学示意，
不输出故障诊断或实车精度结论。

## 四、使用说明（五步以内）

1. 打开公网链接，点首页「开始三分钟演示」（或「体验示例数据」自由探索）；
2. 在运行分析页点任一异常事件：时间轴与曲线游标自动对齐，读数显示原始 CSV 行号；
3. 拖时间轴或曲线寻址、点播放：三维转向架同步做教学回放并高亮相关结构；
4. 展开证据面板：判定规则、起止/峰值观测表、行号范围与非诊断声明；
5. （可选）导入自己的 CSV（速度/横向/垂向加速度列），同一闭环本地复现；三维页可用常驻控制坞
   调光照/线框/透明/粒子/辉光/像素比并导出当前视图 PNG。

## 五、Qoder 开发详细过程（真实贡献，可复核）

**历史边界声明**：本地 Python/Streamlit 完整版（含工程规则与真实数据）为此前由 Codex 协助完成的既有工程，
**不属于本次 Qoder 开发成果**；本次参赛的在线版及其全部前端代码、规则移植、验收与部署由 Qoder 完成。

1. **规则移植不重写口径**：Qoder 阅读原 Python 判定/统计/长间隔规则，移植为浏览器端 `analysis.js`
   （excel 方言 CSV 解析含物理行号、fsum 补偿统计、严格分轴阈值、连续段事件、回放索引），
   并以 Python 生成的 `tests/expected.json` 为基线建 56 项浏览器单测。
   证据：公网 `/tests/index.html` 实时显示「56 / 56 通过 · 全部通过」。
2. **产品化前端与三维查看器**：五入口信息架构、工业暗色视觉、移动端抽屉；基于真实 GLB 契约重建装配 rig
   （layer/holder/spin/link），零件拾取、传感器标签避让、15 控件常驻渲染控制坞（光照/显示/氛围/距离/像素比
   实时作用，导出 PNG）。证据：截图 02/03/04b（见 06 清单）。
3. **证据闭环与导览**：曲线-时间轴-三维-证据四者同游标；三分钟导览每步驱动真实 handler，无硬编码跳过。
   证据：截图 07/09；验收断言 `CSV 第 32 行` 与基线一致。
4. **真实浏览器验收而非 DOM 检查**：Qoder 以 headless Chrome CDP 执行真实渲染+真实输入（真实 CSV 上传、
   拖拽、移动端视口、渲染循环稳定性），本地与公网各跑一遍 **58/58 步 + 56/56 单测 + 0 控制台/网络错误**。
   证据：06 验收表与截图目录。
5. **RC1 独立质量审计（第七阶段）**：Qoder 以外部评审视角重读全部代码，发现并修复 6 项严重三维坐标契约缺陷
   （姿态轴互换、摇头误作俯仰、轮 spin 绕竖轴、悬挂连杆双旋转、枢轴偏移叠加、弹簧不压缩脱开）与 3 项中等问题
   （控制坞状态残留、PMREM 资源未释放、favicon 404），每项附修复前后数值证据，并新增 5 步永久姿态回归。
   证据：12 审计记录、截图 04（播放中悬挂保持连接）。
6. **Qoder Sites 部署与版本核验**：经 Sites MCP prepare/publish，公网与本地 13 项资源逐字节一致
   （index.html 仅托管水印差异），发布操作 ID 与 commit hash 记录于 06。

协作工具：Qoder Sites MCP、CDP 浏览器自动化、子代理代码定位；安全边界：不改主分支、不强制推送、
不提交密钥/数据库/临时产物、原 Python 工程只读。

## 六、创新点摘要（详见 03）

异常→原始行号溯源；口径与 Python 基线逐字对齐；四视图同游标；真实 GLB 契约 rig 与弹簧压缩联动；
测点标签自动避让；导览驱动真实 handler；非破坏性数据返回；单渲染循环无重复加载；诚实标注工程边界。

## 七、工程局限（主动声明）

在线版为教学演示：三维运动是预设包络示意，不是加速度积分重建的实车运动；统计异常不构成故障诊断、
运行安全或法规结论；示例数据为虚构教学批次。完整能力（数据库、批量工程数据）在本地 Python 版。
详见 07。
