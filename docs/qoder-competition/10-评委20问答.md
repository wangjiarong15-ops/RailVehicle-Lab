# 10 · 评委可能提出的 20 个问题与回答

回答口径：只陈述已验收事实；未验证项直接承认（见 07/11）。证据指向源码、单测、验收步骤或截图。

**Q1 既有 Python 项目二次开发，是否符合参赛资格？**
A：参赛资格需赛事官方确认，我们保留该待办（07/11）。材料中已明确历史边界：本地 Python/Streamlit
完整版为此前 Codex 协助完成的既有工程；本次提交的全部在线版代码、规则移植、验收与部署由 Qoder 完成（04/08）。

**Q2 示例数据是真实测得的吗？**
A：不是。示例为虚构教学批次，界面全程带琥珀「虚构演示 · 非实测」徽标（截图 06/09）。
真实能力体现在：导入任意自有 CSV 可本地复现同一闭环，且判定口径与 Python 基线逐值一致。

**Q3 统计异常能当作故障诊断吗？**
A：不能，界面与文档均明确声明。判定是「分轴绝对值严格大于阈值 + 连续段」的统计口径，
用于教学讨论与复核，不构成故障诊断、运行安全或法规结论（07、证据面板声明）。

**Q4 如何保证在线版与 Python 版口径一致，而不是重写了一套规则？**
A：移植时逐条对照原规则（excel 方言解析、fsum 补偿统计、严格大于、3×中位间隔截断、回放索引），
并以 Python 生成的 `tests/expected.json` 为基线建 56 项浏览器单测；公网 `/tests/index.html` 可实时复核 56/56。

**Q5 CSV 行号溯源在多行字段、CRLF、BOM 下还正确吗？**
A：正确。解析器按 excel 方言处理引号内换行/CRLF/BOM，行号为物理行号；单测覆盖 multiline、
引号错误、缺字段、nan/inf、科学计数、时间戳 µs 截断与进位；验收断言事件→「CSV 第 32 行」与基线一致。

**Q6 导入我的 CSV 会上传到服务器吗？**
A：不会。纯前端静态站，无后端；FileReader 本地解析，徽标「本地导入 · 未上传」；
验收含真实上传与非法 CSV 拒载（拒载不破坏已加载数据）。

**Q7 三维模型是随便画的几何体吗？**
A：不是。自包含 GLB 真实装配 + 契约重建 rig（layer/holder/spin/link，`core.js:30`），
零件名称/装配原点/测点位置来自工程契约 `assets/viewer-data.json`；零件点选显示如「左侧 侧梁」与原点坐标。

**Q8 三维运动是实车动力学仿真吗？**
A：不是，是预设包络的教学示意（周期 2.4s 的横向/垂向/摇头包络），界面标注「工况示意 · 非实车测量与诊断」。
我们不做加速度积分重建，也不宣称实车精度（07）。

**Q9 播放时悬挂弹簧会不会和座面脱开？**
A：不会。RC1 审计发现并修复了弹簧不压缩的缺陷：线圈沿连杆轴按当前/静息座距缩放（`core.js:109,136`），
附着误差 0.036→0.0005；58 步验收含 5 步永久姿态回归（横/垂/摇头/自旋/连杆），截图 04 为播放中状态。

**Q10 工程坐标方向如何保证不乱（Z-up vs glTF Y-up）？**
A：契约世界系 Z-up、横向 Y；rig 内建反向旋转世界组抵消 glTF Y-up（`core.js:40-44`），
姿态/自旋/连杆全部在世界组内按工程坐标驱动；回归断言横向只动 Y、垂向只动 Z、摇头只绕 Z、轮心自旋不动。

**Q11 测点位置和方向有工程依据吗？**
A：有。AX1/AX2 为轴箱测点、FR1 为侧梁测点，横向/垂向通道方向向量与工程坐标一致（`viewer-data.json`），
标签含代号与方向并自动避让（`interactions.js:105-137`，截图 03）。

**Q12 页面会不会越用越卡、重复加载模型？**
A：不会。唯一 `renderer.setAnimationLoop`（`app.js:468`），几何/材质/贴图共享、阴影与环境一次性烘焙；
验收六次导航切换 `renderer.info` 恒定 `{g:161,t:3,p:13}`；RC1 另修复 PMREM 生成器未释放问题。

**Q13 移动端能用吗？控件会不会被遮挡？**
A：能。390×844 验收：首页/分析/检视无横向溢出，抽屉+scrim 可开合、导览可操作、控制坞在视口内且动作条
sticky 可见（截图 11–15）；画布 `touch-action:none` 不与页面滚动冲突。

**Q14 没有网络/内网环境能部署吗？**
A：能。Three.js r180 与 addons 全部本地 vendored，无 CDN、无外部请求；静态目录可直接托管或离线打开
（需 http 服务以支持 ES Modules）。新增依赖为零（RC1 未引入任何依赖）。

**Q15 用户输入会不会造成 XSS？**
A：不会。文件名、vehicle_id、错误信息等用户串全部经 `esc()` 转义后入 DOM（`workspace.js`）；
曲线 tooltip 仅使用内部归一化数值，不拼接用户串。

**Q16 控制坞的滑杆是装饰还是真实作用？**
A：真实作用。15 控件直接改灯光强度/方位、环境反射、相机距离、像素比、线框/透明/网格/雾、粒子 drawRange、
辉光透明度、漂移开关；验收逐项断言场景状态变化，恢复默认一键复位（截图 04b/04c）。

**Q17 三分钟导览会不会是硬编码跳过的假演示？**
A：不会。每步驱动真实 handler（真实 click/播放/展开），验收断言导览末步的 selected/row/paused/detail
全为真实状态；重置真实重载示例数据；另有手动兜底路径（05）。

**Q18 验收是 DOM 检查还是真实渲染？**
A：真实渲染。headless Chrome + SwiftShader WebGL，CDP 真实输入事件与真实 CSV 上传、截图目视；
本地与公网各跑 58/58 步 + 56/56 单测 + 0 控制台/页面/网络错误（06）。

**Q19 公网版本如何证明与仓库一致、可回滚？**
A：13 项资源与本地逐字节哈希 MATCH（index.html 仅托管水印差异）；发布操作 ID、commit hash、
本地 rc1 标签与保留的验收目录构成可恢复基线（06/11）。

**Q20 作品的工程局限与下一步是什么？**
A：局限：教学示意非实车仿真、无数据库/批量工程能力（在本地 Python 版）、官方规则与资格待确认。
路线图：真实数据授权后的批次对比、测点扩展、导出报告模板等（07），均不在未验证前宣传为已实现。
