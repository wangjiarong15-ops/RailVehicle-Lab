# 01 · 项目介绍与定位

## 一句话定位

RailVehicle-Lab 是一个**可溯源的轨道车辆转向架工程教学与运行数据分析平台**：把转向架的三维结构、
运行 CSV 的超阈值异常证据、以及原始数据行号放在同一块屏幕上，让「曲线上的一个尖峰」能回答
「对应哪一行原始数据、关联哪个结构、是否足以构成结论」。

## 它解决什么问题

传统运行数据分析里，曲线上的一个尖峰很难回答三个问题：

1. **对应哪一行原始数据？** 多数工具只给时间戳，不给源文件行号，回查源数据靠手工对齐。
2. **关联哪个结构？** 加速度通道与转向架零部件之间缺少可视映射，教学时只能口述。
3. **是否足以构成结论？** 统计超阈值常被误读为「故障诊断」，缺少明确的工程边界声明。

RailVehicle-Lab 把异常事件锚定到**原始 CSV 行号 + UTC 时间戳**，给出判定规则（`|a| > 阈值`，
严格大于、分轴统计）、峰值观测表与相关结构示意，并**明确声明统计异常不构成故障诊断、
运行安全或法规结论**。教学侧则用真实 GLB 装配模型展示零部件、传感器测点方向与工况示意动画，
帮助理解转向架机械结构，而非用虚构几何冒充工程模型。

## 目标用户

- **轨道车辆工程教学**：教师/学生理解转向架装配、一系/二系悬挂、轮对与传感器布点。
- **运行数据分析入门**：工程师/评审快速定位超阈值事件并回查源数据行号。
- **竞赛评审**：无需安装任何环境、无需账号或 API 密钥，打开公网链接即可走完闭环。

## 在线参赛版 vs 本地完整版

| 维度 | 本地完整版（Python/Streamlit） | 在线参赛版（Qoder Sites） |
| --- | --- | --- |
| 运行环境 | Python + Streamlit + 本地数据库 | 纯静态前端，浏览器本地计算 |
| 数据 | 真实工程数据 + 登记配置转换 | 虚构教学示例 + 用户本地 CSV（不上传） |
| 三维 | 工程模型 + 完整工作台 | 同一 GLB 契约 + 教学示意运动 |
| 判定口径 | `rail_vehicle` 规则 | 移植同一口径（`analysis.js`），56 项基线对齐 |
| 证据溯源 | 原始行号 + 数据库台账 | 原始行号 + UTC（无车辆登记台账） |
| 部署 | 本机/便携包 | 公网静态托管，无后端 |

**在线版明确不做**：登记配置转换、传感器登记台账、实车运动重建、故障诊断结论。
这些能力只存在于本地完整版，在线版以 A/B/C 三类诚实标注（见 `workspace.js` 数据源面板）。

## 首次访问如何开始

首页（工作台）直接回答四个问题：是什么、解决什么、怎么开始、哪些是在线演示/哪些仅本地完整版。
三个入口按钮：**体验示例数据**（无需 CSV 走完整闭环）、**开始三分钟演示**（导览驱动真实操作）、
**导入我的 CSV**（仅浏览器本地解析）。默认示例全程带「虚构演示 · 非实测」琥珀徽标。
