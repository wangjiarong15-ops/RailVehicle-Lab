# 04 · Qoder 开发贡献

本项目的工程规则与真实数据来自用户既有的 Python/Streamlit 工程（`rail_vehicle/`，原则上只读）。
Qoder 在第四阶段承担的是**产品化前端、规则移植、验收与竞赛交付**的工程工作，贡献如下（均可在仓库与公网复核）：

## 实际完成的开发工作

1. **在线参赛版前端架构**：设计并实现五入口信息架构（工作台/运行分析/三维转向架/教学仿真/项目说明）、
   工业暗色视觉系统、响应式布局与移动端抽屉（`index.html` / `styles.css` / `app.js`）。
2. **规则移植与口径对齐**：把原 Python 异常判定/统计/长间隔口径移植为浏览器端 `analysis.js`，
   并以 Python 生成的 `tests/expected.json` 为基线建立 56 项浏览器单测，保证不重写口径。
3. **证据溯源闭环**：实现 CSV 行号 + UTC 锚定、事件/观测表、曲线-时间轴-三维-证据四者同步
   （`workspace.js` / `charts.js` / `core.js`）。
4. **三维教学查看器**：基于真实 GLB 契约重建装配 rig、零件拾取/高亮/隔离、传感器标签避让、
   工况示意动画与加载/重试状态（`core.js` / `interactions.js`）。
5. **三分钟可复现导览**：`demo-guide.js` 每步驱动真实 handler，评委无需数据准备即可走完闭环。
6. **真实浏览器验收**：以 headless Chrome CDP 完成 58 步验收（含真实 CSV 上传、拖拽、移动端视口、
   渲染循环稳定性、5 步三维姿态契约回归），本地与公网各跑一遍均 58/58 + 56/56 + 0 错误。
7. **Qoder Sites 部署与版本核验**：通过 Sites MCP 完成 prepare/publish，并逐字节比对公网与本地资源
   （仅托管水印差异），确认线上为最新候选版本。
8. **竞赛材料**：本目录文档、演示分镜、解说词、评委问答、提交清单、架构图与工程局限声明。
9. **第五/六阶段体验深化**：15 控件常驻渲染控制坞（CAE 式专业查看器，含 PNG 导出）与可调氛围层
   （尘埃粒子/测点辉光/待机漂移），全部实时作用、可关可复位，非装饰性假控件。
10. **第七阶段 RC1 独立质量审计**：以外部评审视角重读全部代码，修复 6 项严重三维坐标契约缺陷与
    3 项中等问题（状态残留/PMREM 泄漏/favicon 404），每项附修复前后数值证据并新增永久回归（见 12）。

## 协作方式与工具

- **Qoder Sites MCP**：站点准备、发布、发布状态与交付确认（`prepare_site` / `publish_site` /
  `get_publish_status` / `show_publish_confirmation`）。
- **浏览器自动化（CDP）**：真实渲染与真实输入事件验收，而非仅 DOM 检查。
- **子代理与知识检索**：用于代码定位与基线核对，主代理负责决策与验收。
- **安全边界**：不修改主分支、不强制推送、不提交密钥/数据库/临时产物；原 Python 工程只读。

## 边界声明

Qoder 的贡献是**工程实现与验收**，不构成对工程结论的背书：在线版所有统计来自真实计算，
三维运动为教学示意，不输出故障诊断或实车精度结论（见 07）。
