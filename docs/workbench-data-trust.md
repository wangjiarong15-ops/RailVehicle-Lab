# 工作台数据可信度与恢复

## P0 数据检查

首页原先使用数据库插入顺序处理相同 UTC 时刻，分析和回放从按时间列与记录 ID 回读的序列计算。对同一 UTC 时刻但原始文本不同的旧记录，两套顺序可能不同。首页现在复用同一回读顺序。检测器的默认输出和相邻区段规则保留，图表调用可另取原始样本索引。

横向和垂向分别检测 `abs(a) > threshold`。每个方向的相邻超阈值行合成一个区段，包括正负号变化及采样空档。同方向的未超阈值记录分段。事件时长为首末样本的时间差，空档内的状态未知。图点保持原值、原符号、原时刻和原单位。标记、列表及证据可核对批次行号、采样 ID 和可用的 CSV 物理行号。

导入支持来源未确认、真实测量（用户声明）、测试数据（用户声明）及合成数据。工程接入声明沿用既有来源分类。来源未确认的历史数据维持未确认。预置分析阈值和用户输入阈值均用于统计。当前流程显示“无已核验标准限值”。

## P1 图表与分析记录

首页和常规运行分析共享三通道时间轴和悬停。绘图每通道最多 1,200 条，使用一组采样行，保留桶内极值和本页事件的首条、末条与峰值。统计仍在完整范围运行，高亮区段可跳到既有三维回放和 Copilot 证据路径。重复时间戳共享坐标，悬停显示当前指向的行。同坐标的记录可在逐行窗口按样本顺序核查。首页 20,000 点上限继续指引用户进入完整运行分析。

历史批次的运行分析保存到当前本地 SQLite。记录包含车辆、批次、摘要、数据来源、最近计算时间、阈值、实际批次行范围、UTC 边界和规则版本。用“恢复分析范围”可显式打开该组合。读取记录与恢复时分别核对来源摘要、车辆、批次、范围和算法版本。演示、对比等未生成保存项的记录沿用会话机制。

## P2 界面

首页显示批次来源、可选择的事件高亮、原始峰值行和历史恢复按钮。运行分析的速度与双轴加速度统一显示，历史恢复使用同一个分析入口。

## 复验

运行 `python -m pytest -q` 检查采样、异常、历史库兼容和其他业务。使用 `node scripts/check_phase8_contract.mjs` 对照两端 CSV 计算口径和 54 部件装配。使用 `python -m scripts.run_browser_checks --suite workbench-trust` 在独立虚构数据库中检查同步悬停、原始 CSV 行号、精确三维定位、标签页刷新、全新标签页恢复及 Streamlit 重启恢复。常规浏览器套件 `--suite all` 还会检查三维、PDF、传感器和本机模拟 AI 流式服务。

一次本机微基准对 300,000 条虚构记录进行五次绘图采样，处理时间中位数 224 ms，保留 1,189 条及指定异常峰值。该时间只覆盖绘图选点函数。批次读取、完整统计和浏览器渲染需分别计时。
