# 双版本技术契约 v1

Python 与 Qoder 网页独立运行。共用口径通过 `tests/fixtures/phase8-v1.json` 检验，现场登记、数据库和报告属于完整版能力。

## CSV 与回放

- 必填列为 `timestamp,vehicle_id,speed_kmh,lateral_accel,vertical_accel`。UTF-8 可带 BOM，标准 CSV 引号、逗号及 CRLF 受本轮样本覆盖。物理行从 1 起算，含表头、空行以及引号内部换行，记录定位使用该条记录结束行号。
- 速度采用 km/h，允许 0 至 600。两路加速度采用 m/s²，允许 −100 至 100。边界含端点。要求有限数值和已知车辆标识，空白必填值拒收。
- 时间处理为 UTC；普通 CSV 无显式时区时使用既有默认 UTC 解释，工程声明模式要求显式时区。共同样本对照带时区、微秒、倒序和同一时刻重复记录。重复记录保留，回放按 UTC 时间排序，相同时间在内存准备阶段保持输入顺序。查询历史批次时，传入顺序由数据库查询确定。
- 规则默认阈值 1.0 m/s²。单轴仅在 `abs(value) > threshold` 时产生异常，连续同轴命中按现有异常分组算法聚合。回放估算阈值为正采样间隔中位数的 3 倍，切入超过阈值的间隔时停用该区间状态联动。工程导入另外按声明采样周期的 0.5 倍和 3 倍筛查。
- 数字输出对照采用绝对或相对误差上限 `max(1e-10, abs(expected)*1e-10)`。时间、索引及计数在发布契约样本中应保持一致；临界判断由异常列表及时间区间核验。边界样本包含高低各 1 ULP 和恰等阈值。完整输入语法仍存在差异，例如多余数字下划线和超出网页时间精度范围的日期，现场数据应采用常规十进制和明确时区。

## 装配、坐标和证据

- 工程坐标以轨顶中心为基准，+X 沿车辆纵向由 A 轴指向 B 轴，+Y 向右，+Z 向上，长度为 m。GLB 节点坐标换回工程坐标使用 `(x, -depth, up)`。每个部件的稳定 ID、组、枢轴、运动层与旋转件关系由 `rail_vehicle/bogie_model_spec.py` 生成。两份 GLB 和网页的装配数据与夹具一起检查。
- 原始测量保留源文件摘要、批次、通道、时间与物理行。登记配置绑定安装部件、位置、单位、姿态和时基。轴向换算以当前版本的增益和偏置得到校准值，姿态矩阵用于方向映射；无证据时保持未知，声明与核验状态分别记录。
- 原始测量和依据登记计算的转换结果使用独立数据层。教学动画表达结构和规则事件，数值仿真使用独立模型参数及相对时轴。后两者均不建立现场故障诊断或安全结论。

## 验证与变更

```sh
python -m scripts.build_phase8_contract
node scripts/check_phase8_contract.mjs
```

第一条重算并核对已提交夹具。第二条直接加载在线 RC1 的实际分析模块，核对统计、异常、行号、回放和静态装配。契约变更须先评审，再在开发环境运行 `python -m scripts.build_phase8_contract --write` 更新夹具。对公开比赛部署的验收使用独立发布清单。
