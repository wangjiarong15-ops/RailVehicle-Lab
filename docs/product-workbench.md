# RailVehicle-Lab 产品工作台整合

本轮把主流程集中为四个入口。用户先在综合工作台确认数据是否就绪，在车辆与数据完成导入和运行分析，按需进入三维回查或 AI 证据核查。已有专业工具收纳在「高级选项」，数值计算、SQLite 数据、阈值规则、PDF 及三维模型继续复用。

## 功能清单与导航

| 分类 | 功能 | 整合后的位置 |
| --- | --- | --- |
| 核心 | 数据就绪情况、最新批次摘要、最近分析、下一步 | **综合工作台**。本地按数据就绪状态推荐登记车辆、导入 CSV 或运行分析。公开模式提供虚构数据的三步演示。 |
| 核心 | 车辆登记与编辑、CSV 校验及导入、批次选择、运行统计、阈值事件 | **车辆与数据**。本地三项任务集中在同一模块。公开模式仅提供虚构数据统计和异常演示。 |
| 核心 | 三维转向架、历史或虚构回放、异常区段回查、正常对照 | **三维诊断工作台**。沿用原页面路由和历史事件定位，优先呈现数据来源、模型、当前读数与播放。 |
| 核心 | 查看依据、生成辅助解读、核查 AI 结论、查看历史、离线证据核查 | **AI 分析中心**。没有可核查内容时引导到运行分析。公开模式只提供离线证据核查。 |
| 辅助 | 数据质量、时间和采样说明、批次对比、PDF 报告 | 随运行分析和对应计算提供，报告沿用当前数据范围和计算结果。 |
| 辅助 | 视角预设、零件显隐、剖切、测距、截图、书签、教学拆解、区段导航 | 保留在三维工作台。模型检查工具仍在视窗内，低频的观察和回放设置随对应任务展开。 |
| 专业或低频 | 动态运行驾驶舱、振动与平稳性、多车辆对比 | **综合工作台 → 高级选项**。驾驶舱提供仪表与曲线回放，三维异常回查仍统一指向三维工作台。 |
| 实验或低频 | 机器学习异常检测、演示中心 | **综合工作台 → 高级选项**。保留各实验数据、参数、可用的报告及完整演示入口。 |

原侧栏在本地有 12 项，公开模式有 9 项。整合后，两种模式均只显示四个主模块。首页的下一步与页面内的跨任务按钮按当前上下文保留，例如导入后打开对应批次、从阈值事件跳到三维时间位置。公开模式的三步路线只展示在首页，演示中心集中承载专项实验。历史路由继续服务已有链接和证据跳转。公开模式继续隔离本地数据库、CSV 导入、本地 AI 历史与在线 AI 服务；「三维诊断」表示数据回查及构件观察，页面上的异常仍按测量或规则的实际含义表述。

## 三维现状

- [Blender 建模与装配约定](bogie-glb.md) 采用 X 纵向、Y 横向、Z 向上、长度单位为米。GLB 导出为 Y 向上，浏览器统一恢复坐标。通用示意尺寸为轴距 2.60 m、车轮中心间距 1.76 m、踏面名义半径 0.420 m、轮缘最大半径 0.456 m。它们用于说明模型结构，不代表真实车型尺寸、轨距或许可间隙。
- [Blender 构建脚本](../scripts/build_bogie_blender.py) 已有侧梁和横梁、弹簧座、轮缘及踏面、阶梯车轴、轴箱盖、空气弹簧、制动盘与卡钳、牵引电机和齿轮箱。PBR 使用十种线性 RGB 的基础色、金属度和粗糙度，无外置纹理。
- [54 项装配契约](../rail_vehicle/assets/bogie_viewer/model_contract.json) 由 [Python 结构规范](../rail_vehicle/bogie_model_spec.py) 生成。保留稳定零件 ID、父层、原点、轮轴枢轴和连杆索引。GLB 的四层为构架、走行机构、连接件和固定参照。精修后的资产通过 [GLB 校验](../scripts/validate_bogie_glb.py)，含 54 个零件、54 个网格、47,228 个三角形和 1,377,780 字节。现有预算为 48,000 个三角形及 2,500,000 字节。
- [Three.js 加载器](../rail_vehicle/assets/bogie_viewer/model-loader.js) 检查坐标、装配和枢轴，加载失败回退到程序化几何；项目还保留 Plotly 兼容模式。[光照](../rail_vehicle/assets/bogie_viewer/lighting.js) 已有本地环境反射、主光、补光、轮廓光和阴影。软件 WebGL 播放采用合批和简化光照，暂停恢复完整 PBR。应先改善局部造型与层次，避免单纯提高整体面数。
- [现有动画](../rail_vehicle/assets/bogie_viewer/motion.js) 用固定示意周期、构架相对走行机构的横移和升沉、摇头，以及端点驱动的连杆显示。轮、轴和盘按共用轴线转动，轴箱与卡钳不自转。当前 GLB 连杆沿长度缩放，仍有提高减振器观感的空间。

## 后续数据联动边界

沿用 [回放与阈值映射](../rail_vehicle/bogie_replay.py)、[离线证据范围](../rail_vehicle/replay_evidence.py) 和 [跨页面事件定位](../rail_vehicle/pages/bogie_link.py)。接口可继续演进为三个独立载荷，避免把同一个「异常」字段同时用于数据、规则与动画。

| 载荷 | 最小字段与来源 | 页面表现 |
| --- | --- | --- |
| 观测引用 `ObservationRef` | 来源类别、批次、本地稳定行号或包含首末的行区间、UTC 时间、速度与双轴加速度及显式单位。重复时间戳用行号区分。 | 原样显示导入观测，虚构数据标明来源。长间隔为「无当前观测」，前一观测可另行标注，不能填入当前值。 |
| 规则结果 `RuleAssessment` | 规则版本、阈值和单位、轴向、范围及对应行。由服务端对指定批次重算；双轴事件按同一观测行求交集。 | 显示「横向超阈值」「垂向超阈值」或「双轴同点超阈值」。区段跨度不表示间隙内持续超阈值。 |
| 动画状态 `IllustrationState` | 示意场景 ID、模型契约版本、高亮构件分类、相位或播放状态。可用观测规则选择示意场景。 | 明确标注动画或教学示意。加速度和速度读数不能直接推导真实悬挂位移、轮轨力或零件故障。长间隔回中，不显示当时的异常姿态。 |

AI 和导出图可以引用观测与规则的标识。AI 跳转只接受经服务端验证的批次、阈值和行区间；证据不足时留在一般异常场景。动画、高亮与 AI 推测不反写测量或规则。此接口演进不要求修改原有 SQLite 表。

## 下一轮精修清单

| 顺序 | 实施 | 验收 |
| --- | --- | --- |
| 1. 几何 | 已校准轨顶和踏面，精修轴箱、牵引传动、制动、侧梁端法兰及电机安装座。已对横梁与车轮、侧梁与轴箱两组构件实施离散相位净空检查。 | 同一相机比对几何变化。保留四轮、两轴、54 个稳定 ID、枢轴、父层与网格预算。 |
| 2. 材质 | 先校准构架喷涂、踏面抛光带、轴箱铸件、空气弹簧橡胶的亮度与粗糙度；用少量暗缝和局部高光表现结合面。 | 无网络正常加载；既有正常、选中和规则高亮仍可一眼区分，避免把异常颜色用作装饰。 |
| 3. 光照 | 保留本地环境反射与曝光，收紧主灯阴影范围；暂停观察时评估轻量接触阴影。 | 固定相机、曝光与分辨率做前后截图。分别检查硬件和软件 WebGL 的帧率、绘制次数及暂停恢复，软件播放沿用现有合批路径。 |
| 4. 运动 | 按示意行程将减振器细分为刚性缸筒和活塞，延续端点约束；保持轮轴和盘的相位连续，轴箱和卡钳保持不转，固定轨道不随动。 | 校验播放、暂停、重置、场景切换、缺口回中及最大包络；软件合批识别动态子件，剖切拾取、书签、旧版回退仍可用。 |

建议每批修改后重新导出 GLB，运行结构校验，并用 1366 × 768 与 1920 × 1080 进行同机截图对比。性能需注明浏览器、渲染路径、分辨率和播放场景。模型继续标注为通用工程示意。

## 复验入口

使用现有 Playwright 环境执行 `node scripts/check_product_browser.cjs http://127.0.0.1:8527 screenshots`，第一个地址须运行 `demo_app.py`。可追加 `http://127.0.0.1:8528` 检查 `app.py` 的车辆登记、CSV 导入、PDF 和历史批次回放；该实例应设置独立的临时 `RAIL_PORTABLE_HOME`，因为验收会实际写入虚构车辆和样本。可按 README 设置浏览器路径与软件 WebGL 环境变量。脚本只访问指定的本机服务，不触发在线 AI。
